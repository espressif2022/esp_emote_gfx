# GSP scene package

Use this workflow only for GSP package fixtures under this directory. Runtime
library code belongs in `include/gfx/scene/` and `src/scene/`.

## Required outputs

Every generated package must have two synchronized review artifacts:

1. A machine-consumed `.inc` or `.gsp` package.
2. A human-readable `.manifest.md` package map.

Do not edit generated byte arrays by hand. Regenerate them from the author-side
scene or exporter.

## Binary requirements

- Runtime package data contains no native pointers.
- Object relationships use fixed-width indexes.
- Strings, parameters, blob tables, and blob payloads use byte offsets from the
  package base.
- Multi-byte fields are little-endian and fixed width.
- The header size fields match the generated package.
- The package CRC passes `gsp_crc32_scene()` validation.

Host-only binding tables may remain separate C data, but they must not be
described as part of the portable package payload.

## Manifest requirements

Record the following information:

- source and export reason;
- package version, size, CRC, screen size, and table offsets;
- binary ranges for objects, blobs, parameters, strings, and payload data;
- object indexes, types, parents, rectangles, flags, bindings, and semantic role;
- font and image resource bindings;
- loader API and callback/font binding path;
- exact validation command and result;
- known limitations.

For image blobs, include codec, color format, dimensions, stride, raw size,
compressed size, data offset, and referring object.

## Workflow

1. Update the author-side scene.
2. Export the `.gsp` package.
3. Generate the C `.inc` fixture when required.
4. Dump the package and update its manifest.
5. Run the host loader or headless scene demo.
6. Record the CRC, object count, and self-check result in the manifest.

For the bundled `home` fixture, use the commands in this directory's
`README.md`. Its manifest is `home.manifest.md`.
