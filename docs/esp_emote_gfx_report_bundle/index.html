ESP Native Framework

框架介绍

一个面向 ESP 嵌入式设备的自研轻量图形框架。

当前实现

  • 私有动画格式集成 EAF 序列帧 + Motion 矢量，自研格式，内存极简效率高
  • 多种刷新模式 扫描刷新：针对小内存芯片（ESP32-C2/C3）+ SPI 接口 局部刷新：针对 MIPI/RGB 这类无 RAM 屏幕接口
  • 多种输出格式支持 支持 RGB888 / RGB565 / RGB565 Swap，覆盖更多屏幕规格
  • 资源与文件系统 VFS / mmap / memory 多路径，图片、字体、EAF、Motion、JPG 统一加载
  • 完善的对象树管理 统一对象管理，解决多组件协同问题，为后续组件拓展打基础
  • 本地组件体系 基础控件、图像、文本、动画/进度、列表/Flow，覆盖常用 UI 开发场景
  • 渲染层与硬件后端分离 封装防撕裂（双缓冲 + DMA 异步）、PPA 绘制加速、JPG 硬件解码等芯片能力，硬件层可按平台自动适配
  • SDL 仿真平台支持 不依赖设备运行，PC 直接跑完整 UI，加速开发调试

后期规划

方向

将「运行时构建」转为「编译时构建」，设备端 Build UI → Load Scene。

当前 Runtime Create 机制后续 资源文件编译 机制
计算位置、对齐、布局布局预计算
资源加载、解析、格式转换资源预处理
圆角、描边、阴影等图形计算静态图元预光栅化
创建对象、建立层级、递归遍历对象树构建与优化

收益

  • 减少对象创建、属性解析和布局计算
  • 对象树在编译阶段完成构建与优化
  • 静态图元提前光栅化，降低运行时 CPU 开销
  • 设备端由构建 UI转变为加载场景
  • UI 与业务独立开发：设计只维护 UI，开发只关注业务逻辑
  • 减少大量样板代码：无需维护对象创建、属性设置等 C 代码
  • 降低维护成本：UI 修改无需同步调整创建代码，减少合并冲突
  • 统一资源描述：同一套 UI 资产可适配不同平台 Runtime
  • 资源统一编译：字体、图片、动画等统一转换与打包
  • 自动依赖管理：资源去重、引用分析、按需裁剪
  • 设计与开发并行：UI 与业务独立迭代，减少人工同步
  • 统一资源产物：降低人为错误，提高版本一致性

Anim Space

高效动画引擎

让 ESP 设备用更少内存，跑更稳、更流畅的动画。

解决问题

  • 动画帧率显著提升 解码效率大幅提升，复杂动画依旧丝滑顺畅
  • 内存占用大幅降低 流式解码低内存，ESP32-C2 / C3 也能流畅运行
  • 运行更加稳定 恒定帧率输出，有效消除画面掉帧和抖动
  • 全链路支持 支持 GIF 动画一键转码与设备部署

数据表现

  • 帧率表现 简单动画：约 24 FPS → 约 52 FPS（+120%） 复杂动画：约 20 FPS → 约 45 FPS（+125%）
  • 内存占用 PSRAM：约 538 KB → 约 1.1 KB（下降约 99%）
  • 运行稳定性 传统 GIF：帧率随内容波动明显（18.9 ~ 21.3 FPS） 创新 EAF：帧率稳定在约 45 FPS，波动极小

Motion Runtime

轻量矢量引擎

在 ESP 端侧跑通可交互的矢量角色动画，低内存、高压缩、高帧率。

解决问题

  • 端侧轻量渲染 面向嵌入式设计，摆脱重型引擎依赖，低内存占用
  • 依托成熟设计源 主流设计工具导出的 SVG 可直接复用为端侧矢量动画素材
  • 任意切换，过渡自然 智能补帧算法，任意动画状态瞬时切换、自然衔接，无断层无跳变
  • 空间交互 支持旋转、缩放、平移等空间变换，实时驱动动画
  • 无限无损放大 任意倍率放大，边缘仍清晰平滑、无锯齿模糊 同一动画文件，无需修改即可适配各种分辨率

数据表现

  • 运行帧率 ESP32-S3 · 360×360：稳定 30+ FPS（以龙虾视频为例）
  • 文件体积 传统序列帧 → 单文件最小不到 1K（压缩率提升数百倍）

Roadmap

技术演进方向

围绕动画、矢量、组件与绘制格式，规划下一阶段的演进重点。

01 图像编解码深化 Codec · Compress
构建通用图像编解码能力，覆盖静态图、序列帧等多种载体。 以 EAF 帧动画为起点，持续优化压缩与解码，提升端侧处理效率。
02 矢量技术拓展 Vector · Render
拓展矢量绘制与动画能力，覆盖图标、角色、界面动效等更多场景，打通「设计稿 → ESP 还原」标准路径。 持续优化渲染画质与底层绘制能力，为 GPU 加速铺路。
03 组件可拓展性 Widget · AI Skill
沉淀 widget 与渲染接口的标准化 Skill，便于 AI 自助拓展。 降低组件拓展门槛，支持 AI 快速生成新组件。
04 绘制格式与拓展 Runtime · Descriptive
持续完善 Runtime 代码驱动，贴合现有开发习惯，灵活可编程、易于集成。 UI 从「代码搭建」转为「描述驱动」，描述包经 Runtime 加载为对象树，减少「生成 C 代码→设备转译」环节。
05 沉淀自有图形平台 Foundation · GPU
整合现有 HMI 技术储备，形成可复用的图形技术积累。 建设芯片能力测试与可视化，直观量化 PPA、DMA2D 等硬件加速效果。
